# 节能控制原理与使用说明

这是阶段三实际程序的说明，配合[完整建模原理](C题建模原理说明.md)阅读。当前成果是能够运行、比较和复核的控制原型；数值是指定模型下的仿真结果。

2026年10月18日补充：已完成连续多循环、实际停车恢复和双向测温偏差验证，见[阶段四进展](../results/阶段四进展.md)与[热恢复通俗说明](连续行驶与热恢复通俗说明.md)。下文保留阶段三的实验范围，不能把理想热修正与含停车总账混用。

## 1. 用一句话理解现在做到了什么

我们已经造出一辆“虚拟电动车”，先用真实行驶记录估计部分参数，再让同一辆虚拟车完成同一段行程，比较两套控制规则谁用电更少、温度是否合格。

车速和行程由题目工况决定。控制器能调整的是制动回收、电池冷却、座舱空调和加热，不能通过少开一段路来省电。

## 2. 一步一步发生了什么

1. 从工况读取车速，计算加速度和轮端功率。
2. 计算电机与传动损耗；制动时区分能回收的部分和摩擦制动部分。
3. 加上空调、加热、冷却和低压附件，得到电池端总功率。
4. 由电池模型计算电流、SOC变化和发热。
5. 由热平衡计算电池与座舱下一时刻的温度。
6. 控制器每5秒看一次当前状态，更新下一段时间的动作；仿真以0.5秒积分。

可以把它想成：物理模型负责回答“这样操作会怎样”，控制器负责决定“现在怎样操作”。基准与优化共用物理模型，才能公平比较。

## 3. 电从哪里省下来

### 制动回收：尽量把减速时的能量收回来

基准的名义回收比例为0.65，优化规则选择0.95。它们都是回收请求，实际回收仍受电机功率、SOC和温度限制；并不表示95%的制动能量最终都进入电池。

**通俗解释：** 自行车刹车时动能通常变成刹车片的热；电动车可以让电机反过来发电。但电池太满、太冷或功率太大时不能硬充，多余制动力仍由摩擦制动承担。

项目沿用声明的保守低温规则：−10℃不允许回收，至10℃逐渐恢复。它是新增工程假设，不是已验证的实车标定。因此低温结果不能照搬常温收益。

### 电池冷却：温度合格时减少不必要的冷却

基准采用35℃开、32℃关。优化名义阈值为42℃、回差2℃，但高温初始场景还有相对终温保护：

\[
T_{on}=\min\left(T_{nominal},\ T_{b,initial,sensed}+0.05\right),\qquad T_a\ge35℃.
\]

所以初始40℃时，实际约40.05℃开启；初始35℃时，实际约35.05℃开启。另有44℃强制冷却保护，电池最高温约束为45℃。

**通俗解释：** 像冰箱一样设置开关回差，避免刚开就关、反复抖动。最小开关间隔为30秒。不能只为了表面省电而把电池留下明显更多热量，所以还检查终点温度和热量差。

这些温度与时间阈值是项目设定，不代表电池厂商认证的安全边界。

### 座舱温控：允许小幅变化，同时守住舒适区

共同舒适范围为22—26℃，基准尽量保持24℃。优化在热环境允许更接近25℃、冷环境允许更接近23℃，先利用自然升降温，再按需要开空调或加热。名义偏移请求是1.5℃，为测温误差留1℃余量后，实际目标最多偏移1℃。

座舱热平衡写成：

\[
C_c\dot T_c=H_c(T_a-T_c)+Q_{solar}+Q_{occupant}
+\eta_hP_h-\mathrm{COP}\,P_{ac}.
\]

**通俗解释：** 座舱像一个漏热的房间。外面冷就向外散热，太阳和乘员会带来热量；加热补热，空调搬走热量。先估计需要补多少，再根据温度偏差修正，便于温度平稳地接近目标。

计划到达前300秒统一回到24℃，终点要求24±0.1℃。因此这套策略需要已知计划到达时间；不能声称已解决未知到达时间问题。优化的平均温度偏差更大，报告同时列出这一舒适代价。

空调与电池冷却共享4kW制冷电功率预算，座舱加热不超过5kW。冷却移走的热量和冷却所用电量通过COP换算，不能当成同一个量重复计入。

## 4. “优化”到底怎么算

当前采用有限网格穷举，比较：

| 可选项 | 候选值 | 数量 |
|---|---|---:|
| 名义回收比例 | 0.65、0.80、0.95 | 3 |
| 名义冷却开启温度 | 35、38、40、42℃ | 4 |
| 冷却回差 | 2、3℃ | 2 |
| 请求的座舱偏移 | 0、0.75、1.5℃ | 3 |

共3×4×2×3=72套规则。每套都跑25、40、−10℃三个CLTC场景，先判断约束是否满足，再比较等权平均的修正能耗比例。冻结规则后才做参数扰动与新场景检查，不为每个检查单独选规则。

**通俗解释：** 好比对72组空调和回收设置逐一试车，把不合格的排除，再在合格设置里选平均表现最好的一组。

这只得到候选集合中的最优规则，没有证明所有可能控制方法中的全局最优。MPC需要反复预测未来并求解滚动优化，本项目当前尚未实现MPC。控制器不读取未来车速，也不读取逐时真实SOC、电流、电压来制造预测精度。

## 5. 为什么除了耗电，还要检查“终点留下多少热”

假设方案甲开了空调，方案乙关着空调。乙看起来省电，但如果结束时电池更热，可能只是把冷却推迟到行程之后。

为避免这种影响，环境≥25℃时给优化方案增加理想热量核算项：

\[
E_{b,corr}=\frac{C_b\max(T_{b,opt,end}-T_{b,base,end},0)}{\mathrm{COP}\,3.6\times10^6}\quad(\mathrm{kWh}).
\]

另对两方案的座舱终温差做保守能量换算，定义：

\[
E_{opt,corr}=E_{opt}+E_{b,corr}+E_{c,corr},\qquad
\eta_{save}=\frac{E_{base}-E_{opt,corr}}{E_{base}}\times100\%.
\]

**通俗解释：** 先把“以后可能还要花的冷却电费”作一笔估算，再谈省了多少。

这笔修正没有真实模拟回温过程，忽略实际恢复时的散热、时间与设备工作点等影响，只是公平性诊断。后续必须补充连续多循环和实际恢复过程，才能讨论长时间收益。

## 6. 当前实际结果怎样看

共同条件：CLTC1800秒，初始SOC94%，电池温度等于环境，座舱预先调至24℃；预调温能耗不计入。

| 环境 | 基准端电能 | 优化端电能 | 含理想终态热修正的节能率 |
|---|---:|---:|---:|
| 25℃ | 1.757382kWh | 1.518377kWh | 13.54% |
| 40℃ | 2.192118kWh | 1.868510kWh | 11.41% |
| −10℃ | 3.116439kWh | 3.090073kWh | 0.85% |

三个设计场景满足共同约束。22组扰动与迁移配对中，19组基准和优化均可行；测温偏差+1℃的3组未满足严格真实终温要求，其节能数值只能用于诊断。

**为什么传感器偏差会失败？** 温度计读24℃时，真实温度可能只有23℃。只靠这个有偏测量，无法保证真实温度精确到0.1℃。给舒适区留余量可以保护22—26℃温区，却不能自动修复终点精度。需要校准、独立观测或有依据地重新设计终态指标；本阶段没有删除失败记录或放宽阈值。

22项自动检查通过，说明程序满足对应的物理、接口与数值预期；它不等于22组鲁棒性案例全部成功，更不等于真实车辆已经验证。

## 8. 答辩时需要自己说清的四件事

1. **为什么公平？** 相同车、工况、初值和约束；检查终点温度，并报告理想热量修正与舒适偏差。
2. **为什么省电？** 常温/高温主要来自更多制动回收，低温因回收限制收益小，不能给所有气候套同一节能率。
3. **哪些还没证实？** 没有实测温度，电压跨SOC迁移不足，滚阻接近辨识下界，容量口径冲突未解决；仿真结果不能当实车节能认证。
4. **下一步怎样补强？** 阶段四已补连续与恢复能量、测温偏差分析，并保留失败；继续补参数不确定性，保留真实测温校准和热模型证据缺口，再决定是否引入MPC，最后冻结论文、代码和视频的共同结果。
