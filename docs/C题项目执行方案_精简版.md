# C题项目执行方案：通俗精简版

详细方法见[12步执行方案](C题项目执行方案.md)，公式与解释见[建模原理说明](C题建模原理说明.md)。

## 先记住一条主线

**先造一辆虚拟电动车 → 用真实记录把它调准 → 在里面试节能策略 → 用可靠实验说明效果 → 做成论文、程序和视频。**

推荐用Python。现在没有确定工具，优先采用已有科学计算环境，把数据、模型、校准、优化和绘图放在同一工程里。

## 按12步执行

| 步骤 | 你具体要做什么 | 做到什么程度可以往下走 |
|---|---|---|
| 1. 核对要求和矛盾 | 列出三问和提交要求；记录电池30kWh与160Ah/375V的冲突；核对CLTC来源 | 参数有来源，冲突有处理计划，必做项不遗漏 |
| 2. 整理数据和工程 | 分开四段路程；统一单位、时间和电流方向；画速度、电流、电压、SOC曲线 | 同样操作能得到相同数据，视频短样片能导出 |
| 3. 算车轮和电机 | 根据速度变化算车轮要多少力，再算驱动耗电、制动回收和损耗 | 加速耗电、减速可回收，硬件不超限 |
| 4. 算电池和温度 | 算电流、SOC、电池发热、冷却和车厢温度，让温度反馈内阻 | 电和热能互相影响，冷却和空调都有用电代价 |
| 5. 跑必选基准 | 完成25℃、CLTC，生成能耗、SOC/温度和能量去向 | 各项输出齐全，能量账目对得上，步长减半结果接近 |
| 6. 找关键参数 | 对至少5个参数调大调小，比较影响并排序；建议分析7个 | 清楚哪些最影响耗电、哪些最影响温度 |
| 7. 固定校准方法 | 将路程分训练、验证、测试；明确要估的三个参数、误差和边界 | 测试路程不参与挑参数与方法 |
| 8. 校准并验证 | 估空阻、滚阻、内阻；报校准前后SOC和能耗误差、至少两个参数区间 | 能说明改进多少、哪些参数可靠、哪些地方仍解释不好 |
| 9. 做节能规则 | 先建合理基准，再优化回收、冷却阈值和空调/加热规则 | 同样舒适、安全和行驶条件下，效果可比较 |
| 10. 尝试预测控制 | 根据短期趋势提前安排回收与温控；记录求解耗时与回退 | 算得及时、动作可执行；困难时以优化规则交付 |
| 11. 检验效果是否稳 | 换一个高温或低温场景、扰动参数，关闭一项改进做对照 | 知道策略何时有效、为何有效、何时失效 |
| 12. 整理并提交 | 用同一批结果生成论文、可运行工程和3分钟内视频，单独签承诺书 | 能复现、材料一致、格式合格、系统显示“已提交” |

## 分数优先抓什么

- **模型可信：20分。** 先把功率、能量和温度算对，检查单位与守恒。
- **校准科学：15分。** 既要给参数，也要有独立路程误差、参数区间和局限。
- **数据与仿真连起来：10分。** 数据让模型更准，模型帮助设计和验证策略。
- **优化有证据：10分；创新：10分。** 同条件比较，报告节能、温控和耗时，用迁移或消融说明具体贡献。
- **规范和复现：5分。** 代码能运行、图表清楚、引用和材料一致。
- **视频：30分。** 展示模型、校准、结果、优化对比，动态能量流和曲线要有单位。

这些是评分分值，不保证选择某个算法就能拿到对应分数。

## 三个特别容易做错的地方

1. **把数据读进模型不等于预测。** 可读真实初始SOC，之后应由模型算SOC，不能每一步都用实测答案替换。
2. **关掉空调并不自动证明策略更好。** 必须在相同舒适、安全条件下比较；终点不能把该做的冷却工作全留到后面。
3. **参考数据有矛盾，就先说明。** 电池容量口径和电流/SOC一致性还需排查，不能靠随意调参数把问题藏起来。
