# 连续行驶与热恢复：这次验证了什么

这次主要检查两件事：**车多开一会儿还省不省电？之前少开的冷却，停车后会不会补回来？** 最新数字见[阶段四报告](../results/阶段四进展.md)。

## 1. 为什么要连续跑

一个CLTC循环只有30分钟。像跑步，前半小时表现好，不代表跑三小时也一样。

我们分别连续运行1、3、6个循环，也就是30、90、180分钟。每个循环结束后，电量、温度和冷却开关状态继续保留。车辆不会凭空充满电，也不会突然恢复初温。座舱只在整个行程最后5分钟回到共同的24℃目标。

在暂定模型中，延长行程后仍有节电收益。但校准数据只覆盖约87.68%—100%电量，长行程会降到更低电量；这些结果包含外推，不能当作真实车辆已验证。

## 2. 为什么停车也要算电

假设甲把房间降到24℃，乙只降到26℃。乙暂时用电少，但如果要求最后都达到24℃，就要把后面补开的空调也算上。

电池也会储热。因此我们在驾驶结束后，给两套策略接上**相同的停车温控**，继续计算1小时和2小时的耗电。停车时仍开着座舱空调及附件、保留乘员热和太阳热；全由车载电池供电。这是“带电温控停留”，不是无人熄火停车。

停车电池恒温目标为：40℃环境取31℃，25℃环境取25.1℃，低温不主动冷却。目标和比较阈值都在运行前声明，没有看到结果后为了通过再改。

## 3. 怎样才算比较公平

先检查两套策略各自是否满足舒适、安全、功率和启停约束，再检查结束时温度是否足够接近：

| 检查 | 本次预设要求 | 通俗解释 |
|---|---|---|
| 电池终温差 | 不超过0.2℃ | 不让一方留下明显更多的热 |
| 座舱终温差 | 不超过0.02℃ | 两套方案结束时车厢接近一样 |
| 各自座舱终温 | 24±0.1℃ | 两方都要到共同目标附近 |

这是项目的工程比较条件，不是题目官方温度精度，也不是严格热力学等状态证明。电量可以不同，剩下的电正是需要比较的收益。

驾驶90分钟，再带电停车2小时，暂定模型的结果为：

| 环境 | 总共节省电能 | 总账节能率 | 热终态接近 |
|---|---:|---:|---|
| 25℃ | 0.721 kWh | 11.83% | 是 |
| 40℃ | 0.855 kWh | 9.85% | 是 |
| −10℃ | 0.097 kWh | 0.70% | 是 |

40℃、驾驶180分钟的案例，停车2小时后电池温差仍有0.225℃，超过0.2℃，因此保留“尚未达到接近条件”。它虽满足原舒适和安全约束，也不能算热终态已经对齐。

## 4. 为什么百分比变小，不代表收益全被吃掉

节能率的分母是基准总耗电：

$$\eta=\frac{E_{基准}-E_{优化}}{E_{基准}}\times100\%.$$

停车后，甲乙都要支付维持空调和附件的耗电，分母会增加；同时，乙可能还要多花一些电处理余热。

例如40℃、驾驶90分钟时，两套策略相差1.015kWh。停车2小时后仍相差0.855kWh，减少约0.160kWh。节能百分比下降既包括恢复花电，也包括共同停车耗电增大分母，所以应该同时看“省了几度电”和“省了百分之几”。1kWh就是日常说的1度电。

原来的“理想终态热修正”只是一笔估算账；这次真正向后运行了停车模型。检查点仍有少量热差时，可另外列出残余热量估算，但不能把已经计算过的恢复耗电再算一遍。

## 5. 温度计不准，为什么控制再久也没用

如果温度计总是高报1℃，显示24℃时，真实温度可能接近23℃。控制器会觉得已经到目标，继续等待也不会自动发现温度计有偏差。

本模型使用“热负荷前馈+温差反馈”。在前馈准确、热参数恒定且设备不饱和时，可推导：

$$e_\infty=-\frac{K}{K+H}b.$$

| 符号 | 专业解释 | 人话解释 |
|---|---|---|
| b | 测量固定偏差 | 温度计总是多报或少报多少 |
| e | 真实座舱温度减目标值 | 车里真正偏热或偏冷多少 |
| K | 温度反馈增益 | 发现偏差后，控制器纠偏的力度 |
| H | 座舱环境换热系数 | 车厢与外界传热的程度 |

本项目K=2000W/K、H=60W/K，比例约0.971。因此高报1℃，真实终温约低0.97℃；低报1℃，真实终温约高0.97℃。

7种偏差、3个环境、2套策略，共42个试验。±1℃的12个均未达到24±0.1℃真实终温，不过舒适区22—26℃仍合格。这说明“坐着还舒服”和“精确回到24℃”要求不同。

±0.1℃偏差在精确模型中通过，但最大终温误差约0.09735℃，只剩0.00265℃余量；真实车辆还有热模型误差、测点差异与滞后，不能据此作精度承诺。±0.05℃模拟偏差的最大误差约0.04880℃，也只是为后续误差预算提供参考。

我们没有取得真实校准数据，不能假装已经校准。下一步若要承诺严格真实终温，需要有依据的传感器校准、独立温度参照，或经过验证、能识别偏差的状态估计方法。当前控制器的解析关系不等于所有可能控制器的“不可能性证明”。

## 6. 比赛里怎样表述

可以说：“冻结规则通过连续行驶与共同停车温控验证，在指定模型和有限时长下保留节电收益，同时识别了高温热恢复和传感器精度的适用边界。”

数字应与行程时长、停车范围和参数版本一起出现。尚无实测温度，不能写“已证明实车长期节能”；180分钟高温案例没有达到温差阈值，不能写“全部恢复通过”；传感器试验也没有变成真实校准证据。

本阶段只补验证，没有重新选择原校准参数和控制规则。复现命令：`python run.py stage4`；随后项目工作台会自动同步。
