# V2 拥堵情景的观测依据与可执行参数

本文件替换旧版“在约 68.735 米道路上直接设 1 或 0.5 米/秒”的无观测依据设定。新方案选择 **同一精确几何的完整瑞金二路北行步骤**，从训练期平台预计时间的波动提取相对强度，再对已拟合 SUMO 的有效运行约束施加扰动。**这是有数据锚点的反事实情景，不是还原已观测事故。**

## 1. 使用哪些观测

只用 2026-10-17 **14:55—15:55** 训练窗口的 `west_to_hospital_road` 第 1 步（从 0 编号），按既定 OD／5 分钟桶去重后共 **12 条**。16 条同日后续、96 条跨日留出均不参与取值。源文件、每条时间戳及 SHA-256 见同目录 [scenario_basis_v2.json](scenario_basis_v2.json)。结构化观测快照为 `OBS2_5e1de1d99746ca6d`。

百度返回该步骤距离 **276 米**；按照同一坐标归一化生成的模型几何长度为 **278.665139 米**，差值保留，不强行视为相同。它包含 **19 条有向几何边**，全部精确匹配现有路网；起止 BD09LL 经纬度为 `[121.473142,31.214526]` 至 `[121.472551,31.216977]`。机器可用边列表见 JSON 的 `event_geometry.edge_ids`。

## 2. 强度怎样算

先对每条样本计算整步有效旅行速度：

`u_i = 3.6 × 百度步骤距离（米）÷ 百度步骤预计时间（秒）`。

它包含无法单独拆分的路口及其他延误，**不能解释为点速度、巡航速度或真实道路限速**。12 条的训练中位数是 **6.004119 km/h**，下四分位数是 **4.947344 km/h**，第 10 百分位数是 **4.231714 km/h**。分位数使用 `(n−1) × p` 位置线性插值（type 7），算法及原始样本已保存。

| 情景 ID | 取值 | 对已拟合有效边速度的倍率 | 解释 |
|---|---|---:|---|
| `step_q25` | 训练速度 Q25 / Q50 | 0.823991789 | 训练较慢一侧的相对运行扰动 |
| `step_q10` | 训练速度 Q10 / Q50 | 0.704801929 | 更强的相对运行扰动 |

代码应用为：`事件期间该边有效速度 = 同一个拟合基准中该边有效速度 × 对应倍率`。19 条边使用相同相对倍率，但各自保持原基准速度的差异；结束后恢复各边原值。**不把表中的 km/h 直接当限速赋给道路，也不在已经标定的旅行时间上再叠加整份观测延误。**输出仍由 SUMO 车辆实际运动产生。

倍率将“观测到的综合时间波动”映射为一种明确选择的有效运行机制。它不能判断真实波动来自车流、信号、天气还是道路容量，因此后续论文须保留机制识别边界。速度分位数与时间分位数互为倒数在插值后并不严格成立，本协议固定采用速度分位数，不能混用。

## 3. 为什么不能用路况接口长路段速度直接替代

训练路况中的瑞金二路描述包含“永嘉路到南昌路”等不同区间，长度 **510—1440 米**，速度对应整段，并无返回完整边几何。该范围和上述 276 米步骤不同。JSON 保存了按“道路名＋完整描述＋长度”分组的训练速度分位数，仅用于说明同时段存在慢行；**不进入本步骤的倍率计算，也不在不同区间之间混合取分位数**。

逐步 ETA 来自同一个路线响应，步骤／总 ETA 的比例几乎固定。因此全程 ETA 仍是反演主目标，步骤用于空间定位及诊断，不能再当独立观测重复加权。

## 4. 持续时间的依据与边界

主情景持续 **600 秒**，敏感性为 **300、900 秒**，对应 5 分钟采样间隔的一、二、三个尺度。**这些是公开的实验设计值，不是反演得到的事故时长。**

在同一训练步骤中，低于 Q25 的最初两个快照请求时刻相隔 **325.102 秒**，之后恢复到阈值上方；另有一个孤立低值。首次低值位于窗口开头，事件起点左删失；快照之间状态是否持续也未知。接口没有独立源观测时刻，因此不能据此宣称真实拥堵恰好持续 600 秒。JSON 完整记录连续低值样本组及删失标记。

事件起点、保障任务发布时间、源端控制上限等仍属于实验调度或算法约束，应在运行协议中单列，不能冒充现场测量。固定路线、A、B 各组必须共享相同时间轴、车辆需求、初始状态与事件，比较中计入所有源端等待。

## 5. 完整步骤对可绕行性的影响

19 条事件边中 **13 条／209.930048 米**属于医院方向候选路径的共同必经部分。备选路线只能避开其上游部分，无法避开整个步骤。两条候选路径与事件段的重叠边及长度已在 JSON 中逐项给出。

因此，治理 A 可能无收益或只有有限收益；必须报告实际对照结果。不能为了让 A 获益，在看见结果后把事件缩回原来的 68 米或换到有利位置。

## 6. 复核与机器接口

先重建观测：`python3 -B scripts/prepare_observations_v2.py --run`。在 `route_steps.csv` 中筛选 `phase == training`、`fit_eligible == True`、`route_pair_id == west_to_hospital_road`、`step_index == 1`；应得到 12 条同几何样本。按第 2 节公式重算分位数和比例，即可核对 JSON 的 `estimator` 与 `presets`。

JSON 可直接供治理程序读取：

- `event_geometry.edge_ids`：应用事件的完整有向边列表；
- `presets[*].speed_multiplier`：对应基准各边速度的相对倍率；
- `presets[*].duration_s`、`duration_design.sensitivity_duration_s`：实验设计持续时间；
- `source_observations`、`source_files`：12 条训练证据与全部来源哈希；
- `topology_consequence`：共同必经与候选重叠审计。

本方案的数值来源现在可追溯，但真实道路信号与交通量尚未因此得到实测验证。它支持有来源的参数化实验，不构成真实应急处置效果承诺。
