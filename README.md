# B题：九龙交通数字孪生与治理仿真

使用香港九龙公开道路与交通观测，基于 Python、SUMO 和 TraCI 建立普通交通、入口治理和公共道路应急任务仿真。

本目录是便于 GitHub 阅读与复现的技术归档，论文及 AI 使用材料仍待参赛者本人复核和补充。原始数据的许可、来源及适用条件以相应官方数据和 OpenStreetMap 条款为准；本目录不另行授予第三方资料的许可。

## 仓库与分支

本项目放在 [Xlovlhj/Simulation-Contest](https://github.com/Xlovlhj/Simulation-Contest) 的 `ybs-b` 分支，项目文件位于该分支根目录。上传步骤见 [协作分支上传指南](文档/协作分支上传.md)。本目录是原开发工作区的独立快照。

## Git LFS与下载

支撑ZIP和演示MP4使用Git LFS；源码、PDF及小图片使用普通Git。首次提交前执行 `git lfs install --local`，规则已写入 `.gitattributes`。后续协作者按以下方式下载：

```powershell
git clone --branch ybs-b --single-branch https://github.com/Xlovlhj/Simulation-Contest.git
Set-Location Simulation-Contest
git lfs install --local
git lfs pull
```

确认ZIP和MP4为实际文件后再复现。LFS指针只有几行文本，不是支撑数据本体；网页下载的归档是否包含完整LFS对象取决于仓库设置。使用上述Git克隆方式可明确拉取对象。

## 最短复现流程

安装 Python 3.11 或更高版本，在本仓库根目录打开终端执行：

```powershell
python -m zipfile -e "复现/B题支撑材料_最终修订版.zip" "复现/展开目录"
python "复现/展开目录/reproduce.py" verify
```

这一步只核算已保存结果，使用 Python 标准库，不联网、不启动 SUMO。预期为349次运行、1,919,095条跨运行车辆记录、1,047项成本/未完成字段与2,849个唯一内容校验通过。它不证明真实路况精度或参赛者人工复核。

若要重新执行仿真，另行安装 SUMO 1.27.1，在同一终端设置自己的安装路径，再运行：

```powershell
python -m pip install -r "复现/展开目录/requirements.txt"
$env:SUMO_HOME = "C:\Program Files (x86)\Eclipse\Sumo"
python "复现/展开目录/reproduce.py" run --run-id stage15_conditional_reference_s20261121_conditional --output "复现/重演A"
python "复现/展开目录/reproduce.py" run --run-id stage15_road_s20261125_guarded_green --output "复现/重演道路任务"
```

重演输出目录必须尚不存在。上述命令显式选择冻结输入及正确单位控制；重演不重新请求历史HTTP。顶层源码便于阅读，未展开数据前不具备完整运行输入；最终论文策略的运行入口以这两个复现命令为准。

## 结果边界

- 36次跨日联合精度均未通过，不能称为真实交通准确复现。
- 正确单位治理的21个配对中17个改善、4个恶化，背景车21组全部增加成本。
- 12次道路任务全部到达，但额外让行及延绿零触发，没有新增协同收益证据。
- 一小时运行60次HTTP请求成功，12次更新均保持计划，只证明本次工程运行。
- 67次有限优化未产生合格替换，保留修复原方案，不代表全局最优。
- 349次包含历史错误、失败及诊断，不是349个真实独立样本。

AI对建模、代码、实验、结果及论文有实质参与。本人独立工作、修改复核及真实AI信息仍未补齐；仓库归档和自动检查不等于比赛提交条件已经满足。
